# Этап 2 — проверка и исправление экономики

## Найденные и исправленные ошибки
1. **Списание администратором показывалось в истории как поступление** от администратора. Теперь у каждой операции есть тип (`daily`, `transfer`, `purchase`, `admin_give`, `admin_take`), кто её выполнил (`actor_id`) и пометка.
2. **Одновременные запросы ломали базу** («cannot start a transaction within a transaction»): одиночные записи открывали неявную транзакцию. Соединения переведены в режим автокоммита; денежные операции используют отдельное соединение с явным `BEGIN IMMEDIATE` под блокировкой, поэтому commit обычного обработчика не может завершить их досрочно.
3. **Гонка при первом подключении к базе**: два одновременных запроса открывали два соединения и дважды применяли изменения схемы. Добавлена блокировка инициализации.
4. **Нет предела суммы**: огромные числа могли переполнить SQLite. Лимит одной операции — 10¹² чапов (переводы, выдача, цены).
5. **Покупка с пробелами/заглавными** («  ШАПКА ») не находила товар. Имена нормализуются; пустые и длиннее 32 символов отклоняются.
6. Аргументы-суммы принимаются только из обычных цифр (ранее принимались «экзотические» цифры Unicode).

## Миграции
Добавлен модуль `migrations/` с таблицей `schema_version`. Старая база обновляется без потери данных (покрыто тестом): старые записи получают тип `legacy` и отображаются как раньше.
