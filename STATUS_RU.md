## Текущая стабилизация — 2026-10-16
- Владелец может управлять агентами из личного чата с ботом: `агент добавить <ID_группы> <ID_пользователя>`, `агент удалить <ID_группы> <ID_пользователя>`, `агенты <ID_группы>`. Команды закрыты проверкой `OWNER_TELEGRAM_ID`; группа должна быть зарегистрирована.
- Агенты и модераторы могут отправить сообщение на ручную проверку: ответить на него командой `спам`. Бот создаёт дело и записывает действие в журнал, но не наказывает пользователя автоматически по одной жалобе.
- Добавлена фоновая очистка истёкших наказаний в базе и индекс для ускорения этой операции. Telegram по-прежнему самостоятельно снимает временные ограничения по сроку; база обновляется отдельно.
- Исправлена фиксация автоматического мута после достижения лимита варнов: наказание теперь записывается и попадает в журнал.
- Антиспам проверяет текст, подписи, повторы стикеров и распространённые типы медиа; ограничивает значения настроек безопасным диапазоном и периодически очищает старую историю сообщений.
- Добавлены групповые настройки модулей командами `настройки` и `настройка <модуль> вкл/выкл`, настройка действия антиспама, редактирование текста приветствия и приветствие новых участников.
- Экранированы пользовательские строки в заметках, товарах, кланах, причинах наказаний и журнале, чтобы HTML-разметка в сообщениях не ломалась от пользовательского текста.
- Обработчик XP больше не считает личные сообщения; сроки наказаний проверяются на нулевые и чрезмерно большие значения.
- Проверка: `compileall` и AST-разбор всех 21 Python-файла проходят; базовые проверки утилит прошли. `pytest` по-прежнему не запускается в текущей среде из-за отсутствующего `aiosqlite`. Реальный запуск с Telegram API не подтверждён.


## Дополнительные системы
- Автоответы: `автоответ добавить триггер => ответ`, `автоответы`, `автоответ удалить триггер`; управление доступно модераторам и выше, срабатывание точное и без учёта регистра.
- Дела и апелляции: `обжалование <текст>` при активном наказании; `дела`, `дело ID`, `дело принять ID`, `дело отклонить ID` для модераторов. Принятие апелляции снимает последнее активное наказание, если Telegram позволяет отменить ограничение.
- Ежедневные задания (UTC): 10 сообщений, один перевод, одна покупка. Награды можно забрать командой `задания забрать`; повторное получение предотвращается транзакцией.
- Транзакции экономики и казны клана выполняются на отдельных SQLite-соединениях, чтобы `commit()` обычного обработчика не завершал денежную транзакцию досрочно.
- Проверки текущего изменения: синтаксис/AST для 27 Python-файлов и ручные проверки утилит прошли; SQLite-схема и 8 групп миграций проверены в тестовой in-memory базе стандартной библиотекой. Полный `pytest` и реальный Telegram-запуск всё ещё требуют недоступных в этой среде `aiogram` и `aiosqlite`.

- Экранированы ответы Telegram API в сообщениях об ошибках модерации; имя заметки экранируется в ответе об отсутствии записи.

- Добавлены дополнительные команды модерации: `мои варны`, `варнлист`, `снять все варны`, `муты`, `банлист`, `причина` и `проверить мут`. Они показывают записи из базы; банлист и списки наказаний не могут отображать санкции, которые бот не выдавал и не записывал.
- Добавлены общие команды `мой id`, `кто админ` и `инфо группы`; ошибки Telegram API при получении участников обрабатываются без падения обработчика.
- Проверка ролей использует короткий кэш Telegram API на 30 секунд, чтобы не отправлять запрос `getChatMember` на каждое сообщение; сетевые ошибки больше не прерывают антиспам-обработчик.
- Снижена нагрузка на SQLite: фильтры заметок, браков и кланов теперь читают настройки только для сообщений, похожих на команды этих модулей, а не для каждого сообщения группы.
- Обработчики команд, которым нужен обычный аккаунт, отфильтровывают сообщения без `from_user` (например, отправленные от имени канала), чтобы не падать на обращении к отсутствующему отправителю.
- Команды ручной жалобы `спам` и `пожаловаться на спам` от агентов/модераторов пропускаются через антиспам, чтобы сам антиспам не мешал передавать сообщения на проверку.
